Implement real `node:worker_threads`. `new Worker(filename | code, { eval, workerData, argv, env, resourceLimits })` now spawns an actual thread instead of a listener-map stub: on the container path a thread is a full process worker (worker-per-process — bundled entry + live shim registry over remote deps), reached from the main realm via `ShellService.spawnThreadProcess` and from inside a process worker via new `thread.spawn`/`thread.send`/`thread.terminate` rpc ops; standalone consumers get a browser-`Worker` bootstrap that injects `workerData` + a `parentPort` global. Full API surface: `postMessage`/`on('message')`/`'online'`/`'error'`/`'exit'`, `terminate()` → real kill (resolves exit code), `parentPort`/`workerData`/`isMainThread`/`threadId`, `MessageChannel`/`MessagePort` (native-backed where available) with `receiveMessageOnPort`, `ref`/`unref` handle tracking, `SHARE_ENV`, `setEnvironmentData`/`getEnvironmentData`, `markAsUntransferable`/`markAsUncloneable`/`isMarkedAsUntransferable`, `moveMessagePortToContext`, `postMessageToThread`, `BroadcastChannel`. The same `spawnProcess` seam wires `child_process.fork`/worker-spawn into the registry (stdout/stderr/exit + `process.send`/`process.on('message')` IPC envelopes over the THREAD_MSG transport), and threads a parent exits terminate with it. Known gaps: `resourceLimits` accepted but not enforced, `getHeapSnapshot` unsupported, MessagePort transfer only where the transport is a real postMessage boundary (not across the rpc ops channel).
