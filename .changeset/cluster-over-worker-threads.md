`node:cluster` is now backed by the worker-per-process `worker_threads` backend inside a container: `cluster.fork()` spawns a real `worker_threads.Worker` on the realm's own entry script (`process.argv[1]`) stamped with `workerData.__boloClusterWorkerId`, so the spawned realm's cluster shim detects worker mode (`isWorker`, `cluster.worker`) lazily on first access. IPC rides the existing `IPC_MESSAGE`/`IPC_DISCONNECT` envelopes `process.send`/`process.on('message')` already use; a `__bolo_cluster_msg {act:'listening'}` report (installed by patching `net`/`http`/`https` `Server.prototype.listen`, the `cluster._getServer` seam) drives the primary-side 'listening' event with Node's `{addressType,address,port,fd}` shape. `worker.send`/`disconnect`/`kill`/`destroy`, `isConnected`/`isDead`, `exitedAfterDisconnect`, `process.{exitCode,signalCode,kill}`, `workers`, and the `fork → online → listening → exit` event order are implemented; malformed `NODE_CLUSTER` control messages exit the worker realm with code 0. Outside a container (unit tests, standalone realms) the shim keeps the previous single-process contract: the event/state sequence still fires but no separate realm runs.
