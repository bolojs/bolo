Outside a container (unit tests, standalone realms) the shim keeps the previous single-process contract: the event/state sequence still fires but no separate realm runs.

- [#129](https://github.com/bolojs/bolo/pull/129) [`4005562`](https://github.com/bolojs/bolo/commit/4005562a2bc2441429ca01429c56eb7c0a5730e7) Thanks [@espetro](https://github.com/espetro)! - Implement real `node:worker_threads`. `new Worker(filename | code, { eval, workerData, argv, env, resourceLimits })` now spawns an actual thread instead of a listener-map stub: on the container path a thread is a full process worker (worker-per-process — bundled entry + live shim registry over remote deps), reached from the main realm via `ShellService.spawnThreadProcess` and from inside a process worker via new `thread.spawn`/`thread.send`/`thread.terminate` rpc ops; standalone consumers get a browser-`Worker` bootstrap that injects `workerData` + a `parentPort` global. Full API surface: `postMessage`/`on('message')`/`'online'`/`'error'`/`'exit'`, `terminate()` → real kill (resolves exit code), `parentPort`/`workerData`/`isMainThread`/`threadId`, `MessageChannel`/`MessagePort` (native-backed where available) with `receiveMessageOnPort`, `ref`/`unref` handle tracking, `SHARE_ENV`, `setEnvironmentData`/`getEnvironmentData`, `markAsUntransferable`/`markAsUncloneable`/`isMarkedAsUntransferable`, `moveMessagePortToContext`, `postMessageToThread`, `BroadcastChannel`. The same `spawnProcess` seam wires `child_process.fork`/worker-spawn into the registry (stdout/stderr/exit + `process.send`/`process.on('message')` IPC envelopes over the THREAD_MSG transport), and threads a parent exits terminate with it. Known gaps: `resourceLimits` accepted but not enforced, `getHeapSnapshot` unsupported, MessagePort transfer only where the transport is a real postMessage boundary (not across the rpc ops channel).

### Patch Changes

- [#152](https://github.com/bolojs/bolo/pull/152) [`191db09`](https://github.com/bolojs/bolo/commit/191db096ac05effe6a4e0435181b9aeee037d3ad) Thanks [@espetro](https://github.com/espetro)! - Node core test pass for the Lane-A web shims: `util.inspect`/`formatWithOptions` honor `numericSeparator` (integer digits group in threes from the right, fractions in threes from the left, signs and exponents untouched, BigInts keep `n`); `assert.rejects`/`doesNotReject` render `ERR_INVALID_ARG_TYPE` "Received" text and `ERR_INVALID_RETURN_VALUE` inspect output like Node; `Buffer.from`/`concat` refuse >2^31-1 array-like lengths and total lengths with V8's `Invalid typed array length` RangeError; `perf_hooks` ships a real `PerformanceObserver` over the platform observer plus `PerformanceObserverEntryList`; stream scheduling prefers the container process shim's `nextTick` over `queueMicrotask`; crypto `argTypeError` messages quote strings and name constructors faithfully. The bundle banner's `Console.prototype.clear` now writes Node's `\x1b[1;1H\x1b[0J` sequence to stdout, `node:console` always resolves to the banner console, and rolldown's informational `[EVAL]` warning no longer fails compat runs.

- [#144](https://github.com/bolojs/bolo/pull/144) [`229f749`](https://github.com/bolojs/bolo/commit/229f749ea826c124ad94b8f1e4ec19292090dc70) Thanks [@espetro](https://github.com/espetro)! - Node core-test edge fixes: `util.format` now maps Symbol to `'NaN'` under `%d`/`%i`/`%f` (instead of throwing "Cannot convert a Symbol value to a number"), renders BigInt with its `n` suffix for `%d`/`%i`, uses `parseInt` semantics for `%i`, inspects objects for `%s`, and reports `%j` cycles as `'[Circular: ~]'`. `Buffer.alloc` surfaces V8's `Invalid typed array length: N` RangeError past the 32-bit limit, `Buffer.from`'s `ERR_INVALID_ARG_TYPE` message lists `SharedArrayBuffer` like Node 22, and `Buffer.prototype.toString('utf8')` decodes through `TextDecoder` so invalid sequences consume maximal subparts (one U+FFFD) exactly like V8 — aligning the chunked `StringDecoder` output with a one-shot `Buffer.toString` for `test-string-decoder-fuzz`. `StringDecoder('utf8')` no longer strips a leading BOM, and `crypto.Hmac` gains the legacy `write`/`end`/`read` stream surface Node's `LazyTransform` exposes.

  Sync `child_process` (`spawnSync`/`execSync`/`execFileSync`) now runs for real inside process workers: the worker blocks on the sync channel while the main thread runs the child to completion through a new `child.runSync` op — sibling process workers for `node` specs (bundled file or `-e`/`-p` eval code, whose prelude now exposes `process`/`console`/`Buffer`/`require`), wasm-registry/shell dispatch for non-node commands — then ships buffered stdout/stderr/exit status back and the shim reconstructs Node's result shape (`{ pid, output, stdout, stderr, status, signal, error? }`, `ENOBUFS` on `maxBuffer` overflow, `ENOENT`-style error results). Without a backend the sync APIs keep the documented unsupported error; stdin `input` is not delivered.

  `node:net` gains an in-process `LoopbackTransport` (crossed web-stream pipes: `ECONNREFUSED` on unbound ports, `EADDRINUSE` on double-bind, peer-close EOF), now the default when no `tcpRelay`/custom transport is configured, so `net.Server.listen` + `net.connect` pair client and server sockets inside the container. `new net.Server(options?, listener?)` and `new net.Socket(options?)` now accept the Node arg shapes — a non-transport first arg shifts back to `(options, connectionListener)` instead of failing with `_transport.listen is not a function`.

  `fs` edges: `readFile`/`writeFile`/`mkdir`/`readFileSync`/`writeFileSync`/`mkdirSync` validate their path/data args synchronously (`ERR_INVALID_ARG_TYPE` before any callback or IO, like Node), `readFile*` accept open fds and return a real `Buffer` when no encoding is given (hot-layer reads go through memfs instead of the utf8-string VFS path), `writeFile` honours `flag`/`mode`, and `mkdirSync` forwards memfs' recursive-created-path return. `fs.promises.open` returns a `FileHandle` built on the `vfs.hot` fd family (`close`/`stat`/`truncate`/`chmod`/`chown`/`utimes`/`datasync`/`sync`/`read`/`readFile`/`write`/`writeFile`/`appendFile`/`Symbol.asyncDispose`), which works over a real VfsBus and the worker sync-channel facade alike.

  `process.hrtime(prev)` validates its tuple argument (`ERR_INVALID_ARG_TYPE`/`ERR_OUT_OF_RANGE`) and normalizes the diff borrow so nanoseconds stay non-negative; `process.reallyExit` throws `ProcessExit` without emitting `'exit'` handlers.

- [#116](https://github.com/bolojs/bolo/pull/116) [`52737a2`](https://github.com/bolojs/bolo/commit/52737a2d733fa55f237c69bf97466994c57f37df) Thanks [@espetro](https://github.com/espetro)! - Namespace/export breadth batch: `events` shim is now the EventEmitter class itself with every module-level name (`EventEmitter`, `once`, `on`, `getEventListeners`, `setMaxListeners`, `defaultMaxListeners`, `init`, `EventEmitterAsyncResource`, …) attached as enumerable statics so the bundler's `Object.keys` re-export works; real `StringDecoder` (partial multibyte utf8/utf16le/base64); `os.EOL` configurable + `networkInterfaces`/`cpus`/`tmpdir`/`hostname` fidelity; `util.format`/`inspect` reimplemented (non-string fmt args, circular refs, `inspect.custom`) with `types` wired to the real `util/types`; `assert` argument-validation error codes (`ERR_MISSING_ARGS`/`ERR_INVALID_ARG_TYPE`) + `strict` facade; `path` replaced with a vendored port of Node's `lib/path.js` for correct posix/win32 semantics; `url` reimplemented self-contained so `parse`/`format` no longer hit the dead `node:querystring` external inside unenv. Adds `path/posix`, `path/win32`, `assert/strict`, `util/types` subpath routing to the vite plugin.

### Minor Changes

- [#81](https://github.com/bolojs/bolo/pull/81) [`397f780`](https://github.com/bolojs/bolo/commit/397f780cad0348a5564d46f706045256bda93c17) Thanks [@espetro](https://github.com/espetro)! - Initial public release.

- [#81](https://github.com/bolojs/bolo/pull/81) [`f444253`](https://github.com/bolojs/bolo/commit/f44425329d9f7c1dc7025effb3a2e88dd74b0a62) Thanks [@espetro](https://github.com/espetro)! - Process model: every Node process now runs in its own Worker.

  - Worker-per-process spine with remote dependency loading and a synchronous worker-main channel (SharedArrayBuffer plus sync XHR through the service worker).
  - Real `kill()`: terminating a process tears down its worker and handles.
  - Faithful exit codes: `process.exit()` is uncatchable, uncaught crashes run `exit` handlers and report a non-zero code, and output is gated after exit.
  - Event-loop liveness: handle-tracked timers and servers keep a process alive until idle, with `process.nextTick` queue and macrotask `setImmediate` semantics matching Node.
