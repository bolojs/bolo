## 0.4.0

### Minor Changes

- [#128](https://github.com/bolojs/bolo/pull/128) [`422d0a6`](https://github.com/bolojs/bolo/commit/422d0a6e579f6678108893137cb343da65ae5ed3) Thanks [@espetro](https://github.com/espetro)! - Builtin-sweep batch (compat-matrix fixes). Bundler: injected Node globals (`process`, `Buffer`, `global`, `console`) are now bound as `__bc_*` banner vars with `transform.define` rewrites for unbound references only, so a bundled module that declares its own `Buffer`/`process`/`console` binding no longer hits a parse-time redeclare error. `v8` and `http2` are routed as builtins. Browser-field remaps resolve relative targets against the owning package root (was: importer dir), fixing `enhanced-resolve`-style builtin remaps (`"process": "./lib/util/process-browser.js"`).

  `node-web-shims`: new `v8` shim (heap stats, structuredClone-capable `serialize`/`deserialize`, `setFlagsFromString` no-op) and `http2` shim (`constants`, settings helpers, `Http2ServerRequest`/`Http2ServerResponse`, `sensitiveHeaders`; `connect`/`createServer`/`createSecureServer`/`performServerHandshake` throw `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM`).

  `node-runtime-shims`: `node:module` shim now exports `Module` (constructor + `_nodeModulePaths`, `createRequire`, `builtinModules`, `syncBuiltinESMExports`, `register`, `wrap`, compile-cache stubs), `findPackageJSON`, and `isBuiltin`; registry wires the new `v8`/`http2` shims.

- [#131](https://github.com/bolojs/bolo/pull/131) [`05f331e`](https://github.com/bolojs/bolo/commit/05f331e673022e2b4bcc16c479b237c2b48646ae) Thanks [@espetro](https://github.com/espetro)! - Implement full `node:http` surface (`METHODS`, `STATUS_CODES`, `Server` constructor callable with/without `new`, `OutgoingMessage`, `maxHeaderSize`, `validateHeaderName`, `validateHeaderValue`, `setMaxIdleHTTPParsers`), complete virtual module exports for `node:fs`, `node:fs/promises`, `node:http`, `node:https`, `node:net`, `node:child_process`, `node:dns`, and `node:vm` in `nodeRuntimeShims` Vite plugin, support transparent `base64url` encoding across `Buffer.isEncoding`, `Buffer.from`, `Buffer.prototype.toString`, `Buffer.prototype.write`, and `Buffer.byteLength`, and make `vm.runInNewContext`, `vm.runInContext`, and `vm.createContext` synchronous.

- [#130](https://github.com/bolojs/bolo/pull/130) [`5dc1685`](https://github.com/bolojs/bolo/commit/5dc168521945f50d7b07d9f305a84b69a7871909) Thanks [@espetro](https://github.com/espetro)! - Rework `node:net` around the new faithful `node:stream` port: `net.Socket` is now a real `stream.Duplex` (function-constructor, callable without `new`) with `_read`/`_write`/`_final`/`_destroy` wired to the `ByteTransport` web streams — backpressure-aware incoming pump (`pause`/`resume`/`pipe`/`unshift`), queued writes while connecting, `bytesRead`/`bytesWritten`, `connecting`/`readyState`/`remoteAddress`/`remotePort`/`remoteFamily`/`localAddress`/`localPort`/`address()`, `setTimeout` idle timer emitting `'timeout'`, `setNoDelay`/`setKeepAlive`, and `ref`/`unref` propagating to a `NetHandleTracker` that hooks process liveness via `__browserContainers.timers` (the loop-backed tracked timers) so live connections keep the worker running. `net.Server` is now a function-constructor `EventEmitter` (callable without `new`) with synchronous `listen` returning `this`, `backlog`/`maxConnections`, `'listening'`/`'connection'`/`'close'`/`'error'` events with real Duplex sockets, `getConnections`, `address()`, `listening`, `ref`/`unref`, and coded errors (`ERR_SERVER_ALREADY_LISTEN`, `ERR_SERVER_NOT_RUNNING`, `EADDRINUSE`). Error mapping produces Node-style errno exceptions (`ECONNREFUSED`/`ENOTFOUND`/`EPIPE`/`ECONNRESET` with `code`/`syscall`/`address`/`port`), `isIP`/`isIPv4`/`isIPv6` are ported from Node's validators, `connect`/`createConnection` accept `(options[, cb])`, `(port[, host][, cb])`, and `"host:port"` forms, and the `NoopTransport` path keeps its documented errors.

- [#144](https://github.com/bolojs/bolo/pull/144) [`229f749`](https://github.com/bolojs/bolo/commit/229f749ea826c124ad94b8f1e4ec19292090dc70) Thanks [@espetro](https://github.com/espetro)! - Node core-test edge fixes: `util.format` now maps Symbol to `'NaN'` under `%d`/`%i`/`%f` (instead of throwing "Cannot convert a Symbol value to a number"), renders BigInt with its `n` suffix for `%d`/`%i`, uses `parseInt` semantics for `%i`, inspects objects for `%s`, and reports `%j` cycles as `'[Circular: ~]'`. `Buffer.alloc` surfaces V8's `Invalid typed array length: N` RangeError past the 32-bit limit, `Buffer.from`'s `ERR_INVALID_ARG_TYPE` message lists `SharedArrayBuffer` like Node 22, and `Buffer.prototype.toString('utf8')` decodes through `TextDecoder` so invalid sequences consume maximal subparts (one U+FFFD) exactly like V8 — aligning the chunked `StringDecoder` output with a one-shot `Buffer.toString` for `test-string-decoder-fuzz`. `StringDecoder('utf8')` no longer strips a leading BOM, and `crypto.Hmac` gains the legacy `write`/`end`/`read` stream surface Node's `LazyTransform` exposes.

  Sync `child_process` (`spawnSync`/`execSync`/`execFileSync`) now runs for real inside process workers: the worker blocks on the sync channel while the main thread runs the child to completion through a new `child.runSync` op — sibling process workers for `node` specs (bundled file or `-e`/`-p` eval code, whose prelude now exposes `process`/`console`/`Buffer`/`require`), wasm-registry/shell dispatch for non-node commands — then ships buffered stdout/stderr/exit status back and the shim reconstructs Node's result shape (`{ pid, output, stdout, stderr, status, signal, error? }`, `ENOBUFS` on `maxBuffer` overflow, `ENOENT`-style error results). Without a backend the sync APIs keep the documented unsupported error; stdin `input` is not delivered.

  `node:net` gains an in-process `LoopbackTransport` (crossed web-stream pipes: `ECONNREFUSED` on unbound ports, `EADDRINUSE` on double-bind, peer-close EOF), now the default when no `tcpRelay`/custom transport is configured, so `net.Server.listen` + `net.connect` pair client and server sockets inside the container. `new net.Server(options?, listener?)` and `new net.Socket(options?)` now accept the Node arg shapes — a non-transport first arg shifts back to `(options, connectionListener)` instead of failing with `_transport.listen is not a function`.

  `fs` edges: `readFile`/`writeFile`/`mkdir`/`readFileSync`/`writeFileSync`/`mkdirSync` validate their path/data args synchronously (`ERR_INVALID_ARG_TYPE` before any callback or IO, like Node), `readFile*` accept open fds and return a real `Buffer` when no encoding is given (hot-layer reads go through memfs instead of the utf8-string VFS path), `writeFile` honours `flag`/`mode`, and `mkdirSync` forwards memfs' recursive-created-path return. `fs.promises.open` returns a `FileHandle` built on the `vfs.hot` fd family (`close`/`stat`/`truncate`/`chmod`/`chown`/`utimes`/`datasync`/`sync`/`read`/`readFile`/`write`/`writeFile`/`appendFile`/`Symbol.asyncDispose`), which works over a real VfsBus and the worker sync-channel facade alike.

  `process.hrtime(prev)` validates its tuple argument (`ERR_INVALID_ARG_TYPE`/`ERR_OUT_OF_RANGE`) and normalizes the diff borrow so nanoseconds stay non-negative; `process.reallyExit` throws `ProcessExit` without emitting `'exit'` handlers.

- [#114](https://github.com/bolojs/bolo/pull/114) [`5d18830`](https://github.com/bolojs/bolo/commit/5d188305c1db0f649e54429cde3202ba9c8fc96b) Thanks [@espetro](https://github.com/espetro)! - Broaden `fs` shim surface via memfs (`vfs.hot`/`vfs.vol` passthrough): `realpath*` incl. `.native`, fd API + `fs.promises.open` FileHandle, `rename`/`unlink`/`copyFile`/`appendFile`/`access`/`mkdtemp`/`rmdir`/`truncate`/`chmod`/`utimes`/`cp`/`statfs`, `createReadStream`/`createWriteStream`, `watchFile`/`unwatchFile`, `constants`, stream/stat classes, Node-style callbacks on the async API, and `fs.promises` parity. Expand `process` surface: `env` Proxy with ToString coercion, `arch`/`execPath`/`release`/`features`/`config`, `emitWarning`, `setUncaughtExceptionCaptureCallback`/`hasUncaughtExceptionCaptureCallback` (wired into the process worker's uncaught path), and `getBuiltinModule` resolving through the live registry. Complete `child_process` export shape (`execFile`, `execFileSync`, `ChildProcess`, `spawnfile`/`spawnargs`/`stdio`/`signalCode`, `ref`/`unref`) for globby/del-style imports. Fix timers singleton leak: each live registry now gets its own timers object so the process worker's `Object.assign` no longer mutates the shared unenv module across coexisting containers.

- [#129](https://github.com/bolojs/bolo/pull/129) [`4005562`](https://github.com/bolojs/bolo/commit/4005562a2bc2441429ca01429c56eb7c0a5730e7) Thanks [@espetro](https://github.com/espetro)! - Implement real `node:worker_threads`. `new Worker(filename | code, { eval, workerData, argv, env, resourceLimits })` now spawns an actual thread instead of a listener-map stub: on the container path a thread is a full process worker (worker-per-process — bundled entry + live shim registry over remote deps), reached from the main realm via `ShellService.spawnThreadProcess` and from inside a process worker via new `thread.spawn`/`thread.send`/`thread.terminate` rpc ops; standalone consumers get a browser-`Worker` bootstrap that injects `workerData` + a `parentPort` global. Full API surface: `postMessage`/`on('message')`/`'online'`/`'error'`/`'exit'`, `terminate()` → real kill (resolves exit code), `parentPort`/`workerData`/`isMainThread`/`threadId`, `MessageChannel`/`MessagePort` (native-backed where available) with `receiveMessageOnPort`, `ref`/`unref` handle tracking, `SHARE_ENV`, `setEnvironmentData`/`getEnvironmentData`, `markAsUntransferable`/`markAsUncloneable`/`isMarkedAsUntransferable`, `moveMessagePortToContext`, `postMessageToThread`, `BroadcastChannel`. The same `spawnProcess` seam wires `child_process.fork`/worker-spawn into the registry (stdout/stderr/exit + `process.send`/`process.on('message')` IPC envelopes over the THREAD_MSG transport), and threads a parent exits terminate with it. Known gaps: `resourceLimits` accepted but not enforced, `getHeapSnapshot` unsupported, MessagePort transfer only where the transport is a real postMessage boundary (not across the rpc ops channel).

- [#119](https://github.com/bolojs/bolo/pull/119) [`12bcca5`](https://github.com/bolojs/bolo/commit/12bcca56b7a2752e65acb486c242c6065d50e0de) Thanks [@espetro](https://github.com/espetro)! - Fix process workers crashing at fs-shim construction (`TypeError: Cannot read properties of undefined (reading 'native')`). The fs breadth surface added in the fs-shim expansion assumed `vfs.hot` was a real memfs `IFs`; inside process workers it is an RPC facade, so `hot.realpath.native`, `hot.promises`, `vfs.vol` and `hot.constants` were absent. The worker facade now proxies the full memfs surface the shim touches — `vfs.hot.*` sync ops (incl. the fd family with buffer round-trips), `vfs.hot.<m>` callback methods over async RPC, `vfs.hot.promises.<m>`, `vfs.hot.realpathNative`/`vfs.hot.realpathSyncNative`, `vfs.hot.constants` and `vfs.vol.cpSync`/`vfs.vol.statfsSync` — with the method lists shared between `remote-ops.ts` (main) and `remote-objects.ts` (worker) via `remote-vfs-surface.ts` so the two sides cannot drift again. The fs shim feature-detects the breadth surface at construction: absent members (live objects that cannot cross the boundary — FileHandle, Dir, streams, stat watchers) fail with a clear "not supported by this VFS backend" error at call time instead of a TypeError at construction. The shared RPC marshaller now encodes `undefined` explicitly so optional args no longer arrive as `null` over the sync channel.

## 0.3.0

### Minor Changes

- [#81](https://github.com/bolojs/bolo/pull/81) [`397f780`](https://github.com/bolojs/bolo/commit/397f780cad0348a5564d46f706045256bda93c17) Thanks [@espetro](https://github.com/espetro)! - Initial public release.

- [#81](https://github.com/bolojs/bolo/pull/81) [`f444253`](https://github.com/bolojs/bolo/commit/f44425329d9f7c1dc7025effb3a2e88dd74b0a62) Thanks [@espetro](https://github.com/espetro)! - Process model: every Node process now runs in its own Worker.

  - Worker-per-process spine with remote dependency loading and a synchronous worker-main channel (SharedArrayBuffer plus sync XHR through the service worker).
  - Real `kill()`: terminating a process tears down its worker and handles.
  - Faithful exit codes: `process.exit()` is uncatchable, uncaught crashes run `exit` handlers and report a non-zero code, and output is gated after exit.
  - Event-loop liveness: handle-tracked timers and servers keep a process alive until idle, with `process.nextTick` queue and macrotask `setImmediate` semantics matching Node.
